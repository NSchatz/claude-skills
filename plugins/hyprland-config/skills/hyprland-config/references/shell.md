## Shell Choices

### Bash

The default on most Linux systems. POSIX-compatible, universally available.

| Aspect | Detail |
|--------|--------|
| Config | `~/.bashrc` (interactive), `~/.bash_profile` (login) |
| Completion | Basic; install `bash-completion` for improved support |
| Syntax highlighting | Not built-in; requires plugins (bash-preexec) |
| Auto-suggestions | Not built-in; requires ble.sh or similar |
| Scripting | POSIX-compatible — every shell script works |
| Arch package | Pre-installed (`bash`) |

Best for: users who want maximum compatibility, write lots of shell scripts, or prefer minimal setup.

### Zsh

The most popular shell in the Hyprland/ricing community. Highly extensible with a massive plugin ecosystem.

| Aspect | Detail |
|--------|--------|
| Config | `~/.zshrc` (interactive), `~/.zshenv` (all shells), `~/.zprofile` (login) |
| Completion | Superior tab completion with menu selection, fuzzy matching, descriptions |
| Syntax highlighting | Via `zsh-syntax-highlighting` plugin |
| Auto-suggestions | Via `zsh-autosuggestions` plugin (fish-like) |
| Scripting | Not fully POSIX-compatible but handles most bash scripts |
| Arch package | `zsh` |

Best for: power users who want maximum customization, plugin support, and community resources. The default recommendation for Hyprland setups.

### Fish

Modern, user-friendly shell with sensible defaults out of the box. No configuration needed for syntax highlighting, suggestions, and completions.

| Aspect | Detail |
|--------|--------|
| Config | `~/.config/fish/config.fish` (all sessions), `~/.config/fish/conf.d/*.fish` (modular) |
| Completion | Excellent — parses man pages automatically, inline suggestions |
| Syntax highlighting | Built-in, no plugins needed |
| Auto-suggestions | Built-in, no plugins needed |
| Scripting | NOT POSIX-compatible — different syntax (`set` not `export`, `; end` not `done`) |
| Arch package | `fish` |

Best for: users who want a great interactive experience with zero configuration. The trade-off is that bash/POSIX scripts won't run in Fish — but this rarely matters since scripts use shebangs (`#!/bin/bash`).

**Default recommendation:** Zsh (widest community support, best plugin ecosystem, Hyprland community standard)

## Shell Prompt Theming

### Starship (cross-shell — recommended default)

Written in Rust, extremely fast. Works identically across bash, zsh, and fish. Shows git status, language versions, command duration, and more — all automatically detected.

| Detail | Value |
|--------|-------|
| Config | `~/.config/starship.toml` |
| Arch package | `starship` |
| Font requirement | Any Nerd Font (same one used in terminal/waybar) |

**Initialization by shell:**
```bash
# Bash — add to ~/.bashrc
eval "$(starship init bash)"

# Zsh — add to ~/.zshrc (at the END, after plugins)
eval "$(starship init zsh)"

# Fish — add to ~/.config/fish/config.fish
starship init fish | source
```

**Starter config** (`~/.config/starship.toml`):
```toml
# Use Nerd Font symbols preset as base
"$schema" = "https://starship.rs/config-schema.json"

[character]
success_symbol = "[❯](bold green)"
error_symbol = "[❯](bold red)"

[directory]
truncation_length = 3
truncate_to_repo = true

[git_branch]
symbol = " "

[git_status]
format = '([\[$all_status$ahead_behind\]]($style) )'

[cmd_duration]
min_time = 2000
format = "took [$duration](bold yellow) "
```

Apply a preset for richer defaults:
```bash
starship preset nerd-font-symbols -o ~/.config/starship.toml
# Or for a more minimal look:
starship preset plain-text-symbols -o ~/.config/starship.toml
```

### Powerlevel10k (Zsh only)

The most popular Zsh-specific prompt theme. Extremely fast (instant prompt feature), highly configurable via an interactive wizard.

| Detail | Value |
|--------|-------|
| Config | `~/.p10k.zsh` (generated by wizard) |
| Arch package | `zsh-theme-powerlevel10k` (community repo) |
| Font requirement | Meslo Nerd Font recommended, any Nerd Font works |

**Setup:**
```bash
# Add to ~/.zshrc
source /usr/share/zsh-theme-powerlevel10k/powerlevel10k.zsh-theme

# Run the configuration wizard (first time, or reconfigure):
p10k configure
```

The wizard walks through: prompt style (lean/classic/rainbow), character set, time display, separators, heads/tails, spacing, icons, transient prompt, and instant prompt. It generates `~/.p10k.zsh` with all settings.

**Instant prompt**: Powerlevel10k can display the prompt immediately before plugins finish loading, eliminating visible startup delay. The wizard enables this by default.

### Oh My Posh (cross-shell)

Another cross-shell prompt, configured via JSON/YAML themes. Less popular than Starship in the Linux community but has a large theme gallery.

| Detail | Value |
|--------|-------|
| Config | `~/.config/oh-my-posh/config.json` (or any theme file) |
| Arch package | `oh-my-posh` (AUR) |

Generally recommend Starship over Oh My Posh for Linux/Hyprland — Starship is more widely used and has better Arch integration.

## Plugin Managers

### Zsh Plugin Managers

**Zinit (recommended for Zsh)**

Fast, flexible, supports turbo mode (deferred loading) that dramatically reduces startup time. Plugins load in the background after the prompt appears.

```bash
# Install zinit
bash -c "$(curl --fail --show-error --silent --location https://raw.githubusercontent.com/zdharma-continuum/zinit/HEAD/scripts/install.sh)"

# ~/.zshrc example with turbo loading
source "$HOME/.local/share/zinit/zinit.git/zinit.zsh"

# Load essential plugins with turbo mode (deferred)
zinit wait lucid for \
  atinit"zicompinit; zicdreplay" \
    zdharma-continuum/fast-syntax-highlighting \
  atload"_zsh_autosuggest_start" \
    zsh-users/zsh-autosuggestions \
  blockf atpull"zinit creinstall -q ." \
    zsh-users/zsh-completions
```

**Essential Zsh plugins** (install with any manager):
| Plugin | Purpose | Package (if available) |
|--------|---------|----------------------|
| `zsh-syntax-highlighting` or `fast-syntax-highlighting` | Command syntax coloring | `zsh-syntax-highlighting` |
| `zsh-autosuggestions` | Fish-like inline suggestions | `zsh-autosuggestions` |
| `zsh-completions` | Additional completion definitions | `zsh-completions` |
| `zsh-history-substring-search` | Type partial command, arrow up to search | — |

Arch also provides these as system packages — simpler than a plugin manager if you only need the basics:
```bash
sudo pacman -S zsh-syntax-highlighting zsh-autosuggestions zsh-completions

# Source in ~/.zshrc
source /usr/share/zsh/plugins/zsh-syntax-highlighting/zsh-syntax-highlighting.zsh
source /usr/share/zsh/plugins/zsh-autosuggestions/zsh-autosuggestions.zsh
```

### Fish Plugin Manager

**Fisher (recommended for Fish)**

Lightweight, no framework overhead, pure Fish.

```fish
# Install Fisher
curl -sL https://raw.githubusercontent.com/jorgebucaran/fisher/main/functions/fisher.fish | source && fisher install jorgebucaran/fisher

# Install plugins
fisher install PatrickF1/fzf.fish          # fzf integration (Ctrl+R history, Ctrl+O files)
fisher install jethrokuan/z                 # zoxide-like directory jumping
fisher install catppuccin/fish              # Catppuccin color theme for Fish
```

**Do NOT use Oh My Fish** — it's unmaintained and many packages are broken. Fisher is the community standard.

### Bash Enhancement

Bash doesn't have the same plugin ecosystem, but can be enhanced:

```bash
# Install ble.sh for syntax highlighting + autosuggestions in Bash
# (AUR: blesh-git)
# Add to ~/.bashrc:
[[ $- == *i* ]] && source /usr/share/blesh/ble.sh
```

## Configuration File Locations

### Bash
```
~/.bash_profile    ← Login shell (runs once at login; sources ~/.bashrc)
~/.bashrc          ← Interactive non-login shell (terminal emulators run this)
~/.profile         ← POSIX fallback (read if .bash_profile doesn't exist)
~/.bash_logout     ← Runs on login shell exit
```

### Zsh
```
~/.zshenv          ← ALL shells (login, interactive, script) — keep minimal
~/.zprofile        ← Login shell only (like .bash_profile)
~/.zshrc           ← Interactive shell (where plugins, aliases, prompt go)
~/.zlogin          ← Login shell, after .zshrc
~/.zlogout         ← Login shell exit
```

### Fish
```
~/.config/fish/config.fish       ← Main config (all interactive sessions)
~/.config/fish/conf.d/*.fish     ← Modular config fragments (auto-loaded alphabetically)
~/.config/fish/functions/*.fish  ← Autoloaded function definitions
~/.config/fish/completions/*.fish ← Custom completions
```

Fish uses `~/.config/fish/` exclusively — it doesn't read `.bashrc` or `.profile`.

## Modern CLI Utilities

These Rust-based replacements are popular in the ricing community for better UX, color output, and performance. They integrate well with all three shells.

| Tool | Replaces | Arch package | What it does |
|------|----------|-------------|--------------|
| **eza** | `ls` | `eza` | Git-aware listings, icons, tree view, color-coded file types |
| **bat** | `cat` | `bat` | Syntax highlighting, line numbers, Git diff markers |
| **fd** | `find` | `fd` | Simpler syntax, respects .gitignore, multi-threaded |
| **ripgrep** | `grep` | `ripgrep` | Extremely fast search, .gitignore aware |
| **fzf** | — | `fzf` | Fuzzy finder for files, history, processes; Ctrl+R enhancement |
| **zoxide** | `cd` | `zoxide` | Learns frequently visited directories, `z foo` jumps to best match |
| **delta** | `diff` | `git-delta` | Beautiful syntax-highlighted diffs for git |
| **btop** | `htop` | `btop` | TUI resource monitor with mouse support, themes |
| **dust** | `du` | `dust` | Visual disk usage with bar charts |
| **duf** | `df` | `duf` | Colorful disk free display |
| **procs** | `ps` | `procs` | Human-readable process viewer |
| **fastfetch** | `neofetch` | `fastfetch` | System info display (neofetch is archived — use fastfetch) |

### Initialization by shell

**Zoxide** (add to rc file):
```bash
# Bash
eval "$(zoxide init bash)"
# Zsh
eval "$(zoxide init zsh)"
# Fish
zoxide init fish | source
```

**fzf** (add to rc file):
```bash
# Bash
eval "$(fzf --bash)"
# Zsh
source <(fzf --zsh)
# Fish (use Fisher plugin instead: fisher install PatrickF1/fzf.fish)
fzf --fish | source
```

## Shell Aliases

Generate these based on which CLI utilities the user installs. Only alias tools that are actually installed.

### Bash / Zsh aliases (in `.bashrc` or `.zshrc`)

```bash
# Modern replacements (only if installed)
alias ls='eza --color=always --group-directories-first --icons'
alias ll='eza -la --color=always --group-directories-first --icons'
alias lt='eza -aT --color=always --group-directories-first --icons'  # tree view
alias cat='bat --style=auto'
alias grep='rg'
alias find='fd'
alias diff='delta'
alias du='dust'
alias df='duf'
alias ps='procs'
alias top='btop'

# Convenience
alias ..='cd ..'
alias ...='cd ../..'
alias mkdir='mkdir -pv'

# Hyprland-specific
alias hyprlog='cat /tmp/hypr/$(ls -t /tmp/hypr/ | head -1)/hyprland.log'
alias hyprconf='$EDITOR ~/.config/hypr/hyprland.conf'
alias hyprcheck='hyprctl configerrors'
alias hyprreload='hyprctl reload'
```

### Fish abbreviations (preferred over aliases in Fish)

Fish uses `abbr` instead of `alias` — abbreviations expand inline so you see the real command in history:

```fish
# ~/.config/fish/config.fish
abbr -a ls 'eza --color=always --group-directories-first --icons'
abbr -a ll 'eza -la --color=always --group-directories-first --icons'
abbr -a lt 'eza -aT --color=always --group-directories-first --icons'
abbr -a cat 'bat --style=auto'
abbr -a grep rg
abbr -a find fd
abbr -a top btop

# Hyprland
abbr -a hyprcheck 'hyprctl configerrors'
abbr -a hyprreload 'hyprctl reload'
```

## Terminal Shell Integration

### Kitty

Kitty has built-in shell integration for bash, zsh, and fish. It provides: prompt marking, directory tracking (title bar shows cwd), last command output selection, and more.

```ini
# kitty.conf — shell integration is enabled by default
# To explicitly control features:
shell_integration enabled

# Set default shell (optional — kitty uses $SHELL by default)
# shell /usr/bin/zsh
# shell /usr/bin/fish
```

Kitty automatically sources its shell integration scripts. If using a plugin manager that overrides this, manually source:
```bash
# Zsh — if shell integration isn't working
if [[ -n "$KITTY_INSTALLATION_DIR" ]]; then
  export KITTY_SHELL_INTEGRATION="enabled"
  autoload -Uz -- "$KITTY_INSTALLATION_DIR"/shell-integration/zsh/kitty-integration
  kitty-integration
  unfunction kitty-integration
fi
```

### Foot

Foot supports shell integration via OSC 7 (directory tracking) and OSC 133 (prompt marking). Most shells emit these automatically when running inside foot. No special config needed.

### Alacritty

No built-in shell integration. Relies entirely on the shell's own prompt and features. Simple and predictable.

### Wezterm

Wezterm has shell integration similar to kitty — prompt tracking, clickable URLs, OSC sequences. Configured via its Lua config file.

## Color Scheme Integration

Matching terminal colors to your Hyprland theme creates visual consistency across every window.

### Kitty color themes

```bash
# List available themes
kitty +kitten themes

# Apply a theme (writes to kitty.conf)
kitty +kitten themes --reload-in=all Catppuccin-Mocha
```

Or manually set the 16 ANSI colors + foreground/background in `kitty.conf` to match the chosen palette.

### Fish color themes

```fish
# Catppuccin (via Fisher)
fisher install catppuccin/fish
fish_config theme save "Catppuccin Mocha"

# Or use Fish's built-in theme picker
fish_config theme choose
```

### Zsh / Bash terminal colors

Terminal colors come from the terminal emulator config (kitty.conf, alacritty.toml, etc.), not the shell rc. The shell's syntax highlighting plugin uses these terminal colors automatically.

For **Zsh syntax highlighting** customization:
```bash
# ~/.zshrc — customize highlight colors (optional)
ZSH_HIGHLIGHT_STYLES[command]='fg=blue,bold'
ZSH_HIGHLIGHT_STYLES[alias]='fg=green,bold'
ZSH_HIGHLIGHT_STYLES[path]='fg=cyan,underline'
```

### Pywal / Wallust integration

For dynamic color schemes based on wallpaper:

```bash
# Generate colors from wallpaper
wal -i ~/Pictures/wallpaper.png

# Bash/Zsh — source wal colors on startup
# Add to ~/.bashrc or ~/.zshrc:
(cat ~/.cache/wal/sequences &)

# Fish — add to config.fish:
cat ~/.cache/wal/sequences &
```

Pywal generates template files in `~/.cache/wal/` that can be used for kitty, alacritty, and other apps.

### Starship theme matching

Starship uses its own color definitions in `starship.toml`. To match the Hyprland theme:


## TTY Launch Lines

When the user chooses no display manager (TTY launch), the auto-login line depends on their shell:

**Bash** — add to `~/.bash_profile`:
```bash
[[ -z $WAYLAND_DISPLAY && $XDG_VTNR -eq 1 ]] && exec Hyprland
```

**Zsh** — add to `~/.zprofile`:
```bash
[[ -z $WAYLAND_DISPLAY && $XDG_VTNR -eq 1 ]] && exec Hyprland
```

**Fish** — add to `~/.config/fish/config.fish`:
```fish
if test -z "$WAYLAND_DISPLAY" -a "$XDG_VTNR" = 1
    exec Hyprland
end
```

For **uwsm** users, replace `exec Hyprland` with:
```bash
# Bash/Zsh
[[ -z $WAYLAND_DISPLAY && $XDG_VTNR -eq 1 ]] && exec uwsm start hyprland-uwsm.desktop

# Fish
if test -z "$WAYLAND_DISPLAY" -a "$XDG_VTNR" = 1
    exec uwsm start hyprland-uwsm.desktop
end
```

## Environment Variables and Shells

Environment variables for Hyprland can be set in multiple places. Where to set them depends on the user's session manager and shell:

| Scenario | Where to set env vars |
|----------|----------------------|
| Using uwsm | `~/.config/uwsm/env` (general), `~/.config/uwsm/env-hyprland` (Hypr-specific) |
| No uwsm, any shell | `env =` in `hyprland.conf` (for Hyprland session vars) |
| Shell-specific vars | In the shell's rc file (`.bashrc`, `.zshrc`, `config.fish`) |
| TTY launch (no DM) | Login profile (`.bash_profile`, `.zprofile`, `config.fish`) |

**Fish gotcha**: Fish does NOT read `.profile`, `.bash_profile`, or `.bashrc`. If the user switches to Fish, any env vars previously set in those files need to move to `~/.config/fish/config.fish` using Fish syntax:

```fish
# Fish env var syntax (NOT export KEY=VAL)
set -gx EDITOR nvim
set -gx VISUAL nvim
set -gx BROWSER firefox
```

**Zsh gotcha**: `~/.zshenv` runs for ALL zsh invocations (including scripts). Keep it minimal — only truly universal vars like `EDITOR`. Put session-specific vars in `.zprofile` or `.zshrc`.

## Changing Default Shell

```bash
# List available shells
chsh -l

# Change default shell
chsh -s /usr/bin/zsh    # or /usr/bin/fish, /usr/bin/bash

# Verify (takes effect on next login)
echo $SHELL
```

The install.sh should include the `chsh` command if the user chose a non-default shell, and remind them to log out and back in for it to take effect.
